# IKEA Playwright Test Automation

A Playwright + TypeScript E2E test automation portfolio project for ikea.com/il/he, built to practice test design, the Page Object Model, and CI/CD - with a focus on real-world adaptation, since the target site changed several times during development.

## What's covered

1. **Search & filter** - searches the catalog for a product series (FLISAT), checks that the result counter in the header matches the number of product cards, selects the first color in the filter, and verifies that the number shown under that color matches the result counter after filtering.
2. **Catalog navigation** (menu + carousel) - opens the main menu, navigates the carousel to the kids' category, opens the first product series and checks that the series name appears in the page header. Then opens the first product and verifies that its name matches between the listing card and the product page.
3. **Category carousel + color variants** - navigates the category carousel on the home page to the kids' category, reads the alt text of a product's color-variant image, opens that variant's product page directly and verifies the page header matches the alt text.
4. **Favorites** - starts directly from a catalog page (no repeated navigation), adds the first product to favorites with the heart icon, opens the favorites list from the confirmation message and verifies that the same product (matched by its image alt text) is listed.

## Stack

- [Playwright](https://playwright.dev/) + TypeScript
- Page Object Model
- GitHub Actions (CI)

## Running locally

```bash
npm install
npx playwright install
npx playwright test
```

## CI/CD

Tests run automatically via GitHub Actions on every push. The pipeline installs dependencies and browsers, runs the test suite, zips the Playwright HTML report, and emails it - even if a test fails, so failures are visible without needing to check GitHub manually.

## Known limitations

- The tests run against a live production site. Its content, assortment and search behavior change over time, so tests avoid hardcoded counts and product names where possible, but locators can still break after a site update.
- In the search & filter test, if the first color covers every item in the results, the count check would pass even if the filter did nothing. With the current series this is not the case, but it is a known gap.

## Experiment: Copilot vs hand-written

I compared my hand-written search & filter test with tests generated by GitHub Copilot from a manual-style test case, with a plain and with a more specific expected result. The write-up, with prompts, results and limitations, is in docs/copilot-comparison.md on the copilot-experiment branch.
